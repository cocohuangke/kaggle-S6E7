# 01. 项目分析

## 1.1 竞赛概述

- **竞赛**: Kaggle Playground Series S6E7 — Predicting Student Health Risk
- **任务**: 三分类（at-risk / unhealthy / fit）
- **评估指标**: Balanced Accuracy Score（macro recall）
- **数据规模**: 训练集 690,088 行，测试集 295,753 行
- **数据来源**: 合成数据（College Student Health Behavior Dataset）

## 1.2 目标分布与判分逻辑

### 训练集目标分布

| 类别 | 比例 | 数量 |
|------|------|------|
| at-risk | 85.87% | 592,561 |
| unhealthy | 8.36% | 57,724 |
| fit | 5.77% | 39,803 |

**这是训练集的真实分布，不是需要预测的目标分布。** 我们不需要让预测结果的类别占比接近这个比例。判分逻辑只看每个类的召回率（recall），不关心预测的类别分布。

### 判分公式

```
Balanced Accuracy = (recall_at-risk + recall_unhealthy + recall_fit) / 3
```

平衡准确度（Banlanced Accuracy，简称为BA）就是最终的评分。

其中 `recall_k = 被正确预测为k的样本数 / 实际为k的样本总数`

### 为什么少数类召回率决定最终得分？

用一个例子说明：

**朴素预测（全部预测为 at-risk）**：
- recall_at-risk = 592561/592561 = **1.000**（全对）
- recall_unhealthy = 0/57724 = **0.000**（全错）
- recall_fit = 0/39803 = **0.000**（全错）
- BA = (1.0 + 0.0 + 0.0) / 3 = **0.333**

即使 at-risk 召回率是满分，BA 也只有 0.333。因为 **每个类的召回率权重相同**（1/3），不随类别大小变化。所以少数类（unhealthy 和 fit）的召回率对 BA 的影响与多数类（at-risk）完全对等。

**少数类 = unhealthy + fit**，不是只有 fit。两个少数类合计占 14.13%，但它们对 BA 的贡献占 2/3。提升少数类召回率比提升多数类容易得多（从 0 提升到 0.5 的空间远大于从 0.93 提升到 0.96），所以**优化策略应聚焦于少数类召回率**。

### OOF 的含义

OOF = **Out-of-Fold**，中文译为"折外预测"。

含义：在 K 折交叉验证中，对于第 i 折的验证集样本，模型是用其余 K-1 折的数据训练的——这些样本对模型来说是"折外"的（不在训练折内）。OOF 预测就是每个样本被"没见过它的模型"预测出来的概率值。

意义：OOF 预测近似模拟了模型对新数据的预测能力，比用全量训练集自预测更可靠，避免了标签泄露。CA 校准就是在 OOF 预测上搜索最优乘子——相当于在模拟的"新数据"上调试决策边界，而不是在自己训练过的数据上调。

#### K 折交叉验证的流程

**K 怎么定？** K 是人为选择的超参数，常用 K=5 或 K=10。我们项目用 K=5。K 越大每折训练数据越多（K-1/K），但训练时间也越长（要训练 K 个模型）。

**折是什么？** 把训练数据均分为 K 组，每组中三类目标的比例与整体一致（分层抽样，StratifiedKFold）。以 K=5 为例，690K 行被分为 5 组，每组约 138K 行。

**为什么要分层？** 如果随机分组，某一折的验证集可能全是 at-risk（占 85.8%，随机分组大概率如此），那这折的 OOF 概率对少数类就没有代表性。分层保证每折中 at-risk:unhealthy:fit 的比例都接近 85.8:8.4:5.8。

**分层怎么做？** StratifiedKFold 的做法：先把训练集按目标分成三堆（at-risk 堆 592K 行、unhealthy 堆 58K 行、fit 堆 40K 行），然后每堆各自均分为 K 组，最后从每堆取第 i 组拼成第 i 折。这样每折都有足够数量的少数类样本。

**CA 校准的时机：先算完所有折的 OOF 概率，再统一做 CA 校准。**

流程（以 K=5 为例）：

```
第1折: 用第2-5组训练 → 预测第1组的概率 (138K条)
第2折: 用第1,3-5组训练 → 预测第2组的概率 (138K条)
第3折: 用第1-2,4-5组训练 → 预测第3组的概率 (138K条)
第4折: 用第1-3,5组训练 → 预测第4组的概率 (138K条)
第5折: 用第1-4组训练 → 预测第5组的概率 (138K条)
                              ↓
              拼接5个验证集 → 全部690K条的OOF概率
                              ↓
              在690K条OOF概率上搜索CA乘子（使整体BA最大）
```

### CA 校准的本质

CA = Coordinate Ascent，中文可译为"坐标上升法"。意思是：逐个参数（坐标方向）轮流优化，每次只调整一个，让目标函数值不断上升（提升），直到无法再提升为止。

#### 用本项目的实际例子理解

假设 CatBoost 模型对某条记录输出了三个概率：

```
p_at-risk = 0.60,  p_unhealthy = 0.30,  p_fit = 0.10
```

**不校准时**：取概率最大的那个 → 0.60 最大 → 预测为 at-risk

但假设这条记录的真实标签是 unhealthy。模型给了 unhealthy 0.30 的概率，虽然不低，但 argmax 选择了 0.60 的 at-risk。

**CA 校准的做法**：给每个类的概率乘一个系数（乘子），再取最大的。

假设乘子 τ = (0.5, 1.1, 1.0)：

```
at-risk:    0.60 × 0.5 = 0.30
unhealthy:  0.30 × 1.1 = 0.33  ← 最大！
fit:        0.10 × 1.0 = 0.10
```

校准后 unhealthy 的 0.33 最大 → 预测为 unhealthy → 正确！

**argmax_k 的含义**：argmax 是"取最大值的位置"的意思。k 代表类别（at-risk/unhealthy/fit），argmax_k 就是"哪个 k 让后面的值最大"。不是返回最大值本身，而是返回最大值对应的类别名。

#### 三个乘子是什么

本项目是 3 分类，所以有 3 个乘子：

| 乘子 | 含义 | 效果 |
|------|------|------|
| τ_at-risk | at-risk 概率的缩放系数 | < 1 → 更难被预测为 at-risk |
| τ_unhealthy | unhealthy 概率的缩放系数 | > 1 → 更容易被预测为 unhealthy |
| τ_fit | fit 概率的缩放系数 | > 1 → 更容易被预测为 fit |

本项目实际跑出的乘子：τ ≈ (0.556, 1.095, 0.975)

- at-risk 乘以 0.556 → 概率被砍半 → 很难成为最大值 → 更少被预测为 at-risk
- unhealthy 乘以 1.095 → 概率略微放大 → 更容易成为最大值 → 更多被预测为 unhealthy
- fit 乘以 0.975 → 几乎不变

#### 为什么这有效？用数字感受

不校准时，模型倾向把不确定样本归为 at-risk（因为 at-risk 占 85.8%，模型"见得多"）。考虑 100 个实际是 unhealthy 的样本：

**不校准**：模型可能只正确识别了 50 个（recall=50%），另外 50 个被误判为 at-risk

**校准后**：at-risk 概率被压低，unhealthy 概率被放大。原来 0.45 vs 0.40 的边界情况，变成 0.45×0.556=0.25 vs 0.40×1.095=0.44 → unhealthy 胜出。可能正确识别 70 个（recall=70%）

同时 at-risk 的 recall 会略微下降（比如从 95% 降到 93%），但 BA = (0.93 + 0.70 + 0.95) / 3 = 0.86 > (0.95 + 0.50 + 0.95) / 3 = 0.80。少数类召回率提升带来的收益远大于多数类的损失。

#### CA 的搜索过程

"坐标上升"的搜索过程：

1. 初始乘子 τ = (1.0, 1.0, 1.0)（不校准）
2. 固定 τ_unhealthy=1.0 和 τ_fit=1.0，只调 τ_at-risk：从 0.3 到 3.0 试 300 个值，选让 BA 最大的那个 → 比如 0.6
3. 固定 τ_at-risk=0.6 和 τ_fit=1.0，只调 τ_unhealthy → 比如 1.1
4. 固定 τ_at-risk=0.6 和 τ_unhealthy=1.1，只调 τ_fit → 比如 1.0
5. 回到第 2 步重复，直到 BA 不再提升

整个过程就像拧收音机旋钮——每次只拧一个，找到信号最好的位置，再拧下一个，反复几轮就收敛了。

#### 常见疑问

**Q1：先固定谁后固定谁，结果一样吗？**

不一定完全相同。坐标上升是贪心算法，不同优化顺序可能收敛到不同的局部最优。但在实践中，BA 是一个相对平滑的函数，不同顺序通常收敛到相近的结果。我们项目中固定按 at-risk → unhealthy → fit 的顺序迭代。

**Q2：不同样本给出矛盾信号怎么办？比如某条记录 τ=0.5 更好，另一条 τ=0.7 更好？**

CA 不是逐样本调整的——它是对**全部 OOF 样本**同时计算 BA。具体来说：
- 尝试 τ_at-risk=0.3 → 对全部 690K 条 OOF 记录用 (0.3, 1.0, 1.0) 算新预测 → 算整体 BA
- 尝试 τ_at-risk=0.31 → 同上
- ... 一直到 3.0
- 选让**整体 BA 最高**的那个值

所以不存在"这条记录要 0.3、那条要 0.7"的矛盾——我们选的是让**全部样本**的整体 BA 最优的值。某些样本可能因此被误判，但整体 BA 是提升的。

**Q3：乘子×概率后总和超过 100%，这还是概率吗？**

不是概率了！乘完后确实不满足概率的归一化条件（三个值加起来≠1）。但这没关系——我们不需要它们还是概率，只需要它们的**相对大小**来决定预测类别。

就好比三匹马的速度分别是 60、30、10 km/h，总和 100。乘以 (0.5, 1.1, 1.0) 后变成 30、33、10。我们只关心"33 最大 → 预测为 unhealthy"，不关心 30+33+10=73≠100。

本质上，乘完后的值是**加权得分**——哪个类的加权得分最高就选哪个。乘子调整的是**决策边界**，不是概率本身。

#### 可以手动调整 τ 吗？

可以。τ 没有什么神圣的——它只是一个乘子，你可以手动改。但问题是：**你怎么知道手动调的比 CA 算出来的更好？** CA 是直接优化 BA 的，已经在 OOF 数据上找到了局部最优。

手动调有意义的情况：
1. **CA 收敛到了不好的局部最优**（某个 τ 卡在边界 0.3 或 3.0），可以手动设初始值重新搜索
2. **担心过拟合**：OOF 上的最优 ≠ 测试集上的最优，可以人为把 τ 往 (1,1,1) 方向拉一点做正则化
3. **有领域知识**：比如"unhealthy 召回率太低，想再放宽"，可以手动把 τ_unhealthy 调大

我们项目中 CA 算出的 τ ≈ (0.556, 1.095, 0.975)，都在合理范围内，没有卡在边界，手动调的收益不大。

### 算法设计启示：少数类应放宽预测门槛

从 BA 公式可以推出一个关键优化策略：**少数类应该更容易被预测，多数类应该更难被预测。**

推理过程：

1. BA 中每个类的权重相同（1/3），但 at-risk 占 85.8%，unhealthy 占 8.4%，fit 占 5.8%
2. 模型默认倾向于把不确定的样本归为 at-risk（因为 at-risk 先验概率高）
3. 这导致少数类（unhealthy, fit）的召回率偏低
4. 要提高少数类召回率，需要**降低**预测为少数类的门槛——让更多"可能"是少数类的样本被预测为少数类
5. 同时**提高**预测为 at-risk 的门槛——避免过多本应是少数类的样本被错误归为 at-risk

**注意**：这里"严格"的方向容易搞反。直觉上可能认为"少数类更重要所以要更严格"，但实际上恰好相反——少数类要**更宽松**地预测（宁多勿漏），多数类要**更严格**地预测（宁少勿多）。

CA 校准的乘子正好体现了这一点：at-risk 的 τ ≈ 0.5（缩小，更难被预测），unhealthy/fit 的 τ ≈ 1.0-1.1（放大，更容易被预测）。

这个洞察可以指导算法设计的多个方面：
- **损失函数**：Focal Loss / class_weight 让模型更关注少数类
- **采样策略**：过采样少数类 / 欠采样多数类
- **后处理**：CA 校准调整决策边界
- **OvR 策略**：为每个少数类单独训练二分类器，独立调优阈值

## 1.3 特征体系

### 原始特征（13个）

**数值（7）**:

| 特征 | 含义 | 区分力 |
|------|------|--------|
| sleep_duration | 每日睡眠时长（小时） | **强**（fit 睡更多） |
| heart_rate | 静息心率（次/分） | **弱**（三类均值几乎相同） |
| bmi | 体质指数 = 体重(kg) / 身高(m)² | 中 |
| calorie_expenditure | 每日热量消耗（千卡） | **弱**（三类差异极小） |
| step_count | 每日步数 | **强**（fit 步数更多） |
| exercise_duration | 每日运动时长（分钟） | **强**（fit 运动更多） |
| water_intake | 每日饮水量（升） | **弱**（三类均值几乎相同） |

**类别（6）**:

| 特征 | 取值 | 区分力 |
|------|------|--------|
| diet_type | veg / balanced / non-veg | 弱 |
| stress_level | low / medium / high | **极强** |
| sleep_quality | poor / average / good | 中 |
| physical_activity_level | sedentary / moderate / active | **极强** |
| smoking_alcohol | yes / no / occasional | 弱 |
| gender | male / female / other | 弱 |

### 缺失值

| 特征 | 缺失率 | 重要性 |
|------|--------|--------|
| stress_level | 12.00% | **最高**（stress×activity 近似决定 target） |
| sleep_duration | 11.01% | 高（区分 fit vs unhealthy） |
| sleep_quality | 8.45% | 中 |
| calorie_expenditure | 7.66% | 低 |
| water_intake | 6.30% | 低 |
| physical_activity_level | 5.31% | 高 |
| 其余 | 1-4% | 低 |

### 关键发现：stress_level × physical_activity_level 近似决定 target

**"桶"的含义**：将 stress_level（3个取值）和 physical_activity_level（3个取值）做交叉分组，得到 3×3=9 个组合，每个组合称为一个"桶"（bucket）。桶内的样本具有相似的 target 分布。

**9个桶的 target 分布**：

| 桶 | stress_level | physical_activity_level | at-risk | unhealthy | fit |
|----|-------------|----------------------|---------|-----------|-----|
| low_active | low | active | 41.8% | **57.9%** | 0.3% |
| low_moderate | low | moderate | **99.5%** | 0.3% | 0.2% |
| low_sedentary | low | sedentary | **99.5%** | 0.3% | 0.2% |
| medium_active | medium | active | **99.3%** | 0.4% | 0.3% |
| medium_moderate | medium | moderate | **99.5%** | 0.3% | 0.2% |
| medium_sedentary | medium | sedentary | **99.5%** | 0.3% | 0.2% |
| high_active | high | active | 70.0% | 0.4% | **29.5%** |
| high_moderate | high | moderate | 72.1% | 0.3% | **27.6%** |
| high_sedentary | high | sedentary | 73.0% | 0.3% | **26.7%** |

**完整推导过程**：

1. **9个桶中有6个几乎是纯 at-risk**（99.3-99.5%）。这些桶覆盖了 stress=low/moderate 的所有 activity 水平，以及 stress=medium 的所有组合。这6个桶包含了训练集的大部分样本。

2. **low_active 桶是唯一以 unhealthy 为主的**（57.9%）。这意味着：当压力低且运动量高时，人更可能是 unhealthy 而非 at-risk。直觉上：低压力+高运动 → 身体在运动但可能存在潜在健康问题（不健康但没感到压力）。

3. **high_* 三个桶中 fit 类出现**（~27-30%）。这意味着：当压力高时，无论运动量多少，都有约 30% 的概率是 fit。直觉上：高压力可能来自高强度训练/工作，这类人虽然压力大但身体素质好。

4. **推论**：模型的核心任务不是区分 at-risk（太容易了，占 85.8%），而是：
   - **识别 low_active**：这是唯一能区分 unhealthy 的模式
   - **识别 high_***：这是唯一能区分 fit 的模式
   - 其余 6 个桶几乎全是 at-risk，无需精细区分

5. **stress=high 时 fit 占 ~30%，说明什么？** 这说明 stress_level 单独不能决定结果——high stress 下 at-risk 仍占 70%。必须结合 physical_activity_level 才能进一步区分。这也解释了为什么 stress_x_activity 交互特征如此重要：它捕获了两个特征的联合分布信息。

### 弱区分力特征分析

仅看均值差异容易误判。用 Cohen's d 效应量（|d| < 0.2 = 微弱，0.2-0.5 = 小，0.5-0.8 = 中，> 0.8 = 大）严格衡量：

| 特征 | at-risk vs unhealthy | at-risk vs fit | 判定 |
|------|---------------------|----------------|------|
| heart_rate | d=0.019 | d=0.036 | **垃圾**（所有 d < 0.06） |
| water_intake | d=0.000 | d=0.019 | **垃圾**（几乎无区分力） |
| calorie_expenditure | d=0.088 | d=0.451 | **弱**（at-risk vs fit 有小效应） |
| sleep_duration | d=1.836 | d=0.888 | **极强** |
| step_count | d=0.067 | d=0.970 | **强**（at-risk vs fit） |
| exercise_duration | d=0.073 | d=0.878 | **强**（at-risk vs fit） |

**heart_rate 和 water_intake 确实是垃圾**：三类均值差异极小，且类内方差极大（heart_rate std≈8.1，类间均值差仅 0.2-0.5）。信噪比太低。

**calorie_expenditure 不是完全垃圾**：at-risk vs fit 有 d=0.45 的小效应，fit 比其他类消耗更多热量（2364 vs 2215-2245），有合理性（健康人运动多→消耗多）。但在我们的测试中，删除它对结果无影响。

**能否通过函数放大微小差异？** 理论上可以（如取 log、平方、交互），但实际效果有限。因为放大均值差的同时也放大方差，信噪比不变。更有效的做法是**交互特征**：heart_rate 单独没用，但 heart_rate × stress_level 可能有用（压力大+心率高的组合可能指向 unhealthy）。我们已做了 `stress_x_heartrate` 交互，实测贡献仍小——根本原因是信噪比太低。

## 1.4 特征工程详解

### 从 13 维到 110 维的完整过程

原始数据只有 7 个数值 + 6 个类别 = 13 个特征。通过以下步骤扩展到 ~110 维：

#### Step 1: 缺失指示器（+13维）

对每个原始特征创建一个二值列 `X_missing`，标记该值是否缺失。这让模型能区分"真实的低值"和"缺失后填补的值"。

```python
full['sleep_duration_missing'] = full['sleep_duration'].isnull().astype(int)
```

数值缺失用中位数填补，类别缺失用 'missing' 字符串填补。

#### Step 2: 类别交互（+7维）

将两个类别特征拼接成新类别，捕获联合分布：

```python
full['stress_x_activity'] = full['stress_level'] + '_' + full['physical_activity_level']
# 例如: 'low_active', 'high_sedentary' 等 9 个取值
```

创建的交互：stress_x_activity, stress_x_sleep_quality, activity_x_diet, stress_x_smoking, sleep_x_quality, activity_x_smoking, diet_x_smoking

#### Step 3: 序数评分（+5维）

将有序类别映射为整数，保留顺序信息（LabelEncoder 不保留顺序）：

```python
stress_map = {'low': 1, 'medium': 2, 'high': 3, 'missing': 2}
full['stress_score'] = full['stress_level'].map(stress_map)
```

创建：stress_score, activity_score, sleep_quality_score, diet_score, smoking_score

#### Step 4: 临床特征（+12维）

基于领域知识构建的派生特征：

```python
full['bmi_category'] = pd.cut(full['bmi'], bins=[0, 18.5, 25, 30, 100])  # 体重分类
full['sleep_deficit'] = 8 - full['sleep_duration']  # 睡眠不足量
full['activity_volume'] = step_count * 0.01 + exercise_duration * 0.5  # 活动总量
full['cardio_stress_index'] = heart_rate * stress_score  # 心血管压力
full['sedentary_risk'] = (step_count < 5000) & (sleep_quality == 'poor')  # 久坐风险
full['sleep_deprived'] = (sleep_duration < 5)  # 睡眠剥夺
full['recovery_ratio'] = sleep_duration / (exercise_duration + 1)  # 恢复比
# ... 还有 active_min_per_1k_steps, calories_per_1k_steps, sleep_effectiveness, exercise_intensity, hydration_efficiency
```

#### Step 5: 数值交互（+12维）

两个数值特征的乘积/比值，捕获非线性关系：

```python
full['bmi_x_exercise'] = bmi * exercise_duration
full['sleep_x_stress'] = sleep_duration * stress_score
full['stress_x_heartrate'] = stress_score * heart_rate
# ... 还有 steps_x_exercise, calorie_per_step, heart_rate_x_bmi, water_x_exercise 等
```

#### Step 6: KMeans 聚类（+2维）

**KMeans 不是原始数据提供的，是我们自己推导的。** 过程：

1. 对训练集的 7 个数值特征做 StandardScaler 标准化
2. 用 KMeans(n_clusters=5) 在标准化后的数据上聚类
3. 对每个样本生成两个新特征：
   - `cluster`：所属簇编号（0-4，作为类别特征）
   - `cluster_dist`：到最近簇中心的距离（连续值，越小表示越典型）

```python
scaler = StandardScaler()
kmeans = KMeans(n_clusters=5, random_state=42, n_init=10)
kmeans.fit(scaler.fit_transform(train[num_cols]))
full['cluster'] = kmeans.predict(scaler.transform(full[num_cols]))
full['cluster_dist'] = np.min(kmeans.transform(scaler.transform(full[num_cols])), axis=1)
```

#### Step 7: KBins 离散化（+7维）

**KBins 也不是原始数据提供的，是我们推导的。** 将每个数值特征分成 10 个分位数桶，转为整数：

```python
binner = KBinsDiscretizer(n_bins=10, encode='ordinal', strategy='quantile')
full['sleep_duration_bin'] = binner.fit_transform(full[['sleep_duration']])
```

这让树模型可以在更粗的粒度上分裂，有时能减少过拟合。

#### Step 8: Target Encoding（+39维）

**Target Encoding 是我们自己推导的，不是原始数据提供的。** 它是最重要的特征扩展步骤。

**原理**：对于类别特征 X 的每个取值 x，计算在该取值下目标变量 Y 属于每个类 k 的概率：

```
TE(x, k) = (count(X=x, Y=k) + smoothing * global_prob_k) / (count(X=x) + smoothing)
```

- `global_prob_k`：类 k 在全训练集的比例（先验）
- `smoothing`：平滑参数（我们用 10），控制先验权重
- 当 count(X=x) 很大时，TE ≈ 局部概率；当 count(X=x) 很小时，TE ≈ 全局概率

**OOF（Out-of-Fold）Target Encoding**：

**"泄露"是什么？** 如果用全训练集计算 TE，再用同一个训练集训练模型，模型就"看到了"自己的标签信息——这就是标签泄露（target leakage）。泄露导致模型在训练集上表现虚高，但在测试集上表现下降。

**OOF 如何防止泄露？** 将训练集分成 K 折，对于第 i 折的样本，只用其余 K-1 折的数据计算 TE。这样每个样本的 TE 值都不包含自己的标签信息。

```python
# 对 stress_x_activity 做 OOF TE（5折）
for trn_idx, val_idx in KFold.split(train):
    # 只用 trn_idx 的数据计算 stress_x_activity='low_active' → at-risk 的概率
    te_value = count(trn, X='low_active', Y='at-risk') / count(trn, X='low_active')
    # 赋值给 val_idx 的样本
    encoded[val_idx] = te_value
```

**平滑编码**：当某个类别取值出现次数很少时（如 stress_x_activity='missing_missing' 可能只有几十个样本），直接计算的比例不稳定。平滑公式将小样本的 TE 拉向全局概率，避免极端值。

**我们 TE 了 13 个类别列**（stress_x_activity, stress_level, physical_activity_level, stress_x_sleep_quality, sleep_quality, activity_x_diet, diet_type, smoking_alcohol, gender, bmi_category, sleep_x_quality, cluster, ...），每列生成 3 个概率值（at-risk/unhealthy/fit），共 13×3 = 39 维。

### 特征工程常见疑问

**Q1: 缺失指示器 — 能不能直接删掉有缺失的行？**

690K 行中，stress_level 缺失 12%（83K行），sleep_duration 缺失 11%（76K行）。多个特征都有缺失，如果删除"任一特征缺失"的行，大约会丢掉 **30-40%** 的数据（不同特征的缺失不完全重叠）。这太多了。

更重要的是：缺失本身可能携带信息。比如 stress_level 缺失的人可能是不愿填写压力问卷的人——这类人可能更倾向于 at-risk。缺失指示器让模型能学到这种"缺失模式"。

**Q2: 类别交互 — 为什么选这7个？为什么只有2个特征组合？**

选这7个是**经验+领域知识**驱动的，不是系统搜索的结果：
- stress_x_activity：已知最强交互（近似决定 target）
- stress_x_sleep_quality / stress_x_smoking：压力常与睡眠/吸烟相关
- activity_x_diet / activity_x_smoking / diet_x_smoking：生活习惯常相关
- sleep_x_quality：睡眠时长和睡眠质量应相关

**为什么没有3特征交互？** 3特征交互会产生太多取值。stress(3) × activity(3) × sleep_quality(3) = 27 个取值，很多桶样本极少，TE 不稳定。2特征交互是效果和稳定性的平衡点。但可以尝试3特征交互，需配合更大的 smoothing 参数。

**Q3: 序数评分 — 和类别特征同源重复？会不会拉高权重？**

是同源信息，但表达方式不同：
- LabelEncoder: stress_level = {0, 1, 2}，模型不知道 1 在 0 和 2 之间
- stress_score: stress_level = {1, 2, 3}，模型知道顺序

树模型分裂时，LabelEncoder 只能做 "≤1" 的分裂（低/中 vs 高），score 版本可以做更灵活的分裂。两者提供不同视角，不完全重复。

**会不会拉高权重？** 树模型通过分裂增益自动选择特征，同源特征不会简单叠加权重。如果 score 版本更好用，模型选它；如果 LE 版本更好用，选它；差不多则分散使用。

**Q4: 临床特征阈值 — 8小时睡眠、5000步不科学？同源反复强调？**

阈值来自一般健康指南（WHO建议成人7-9小时睡眠，久坐定义<5000步/天），**确实是武断的**。更好的做法是用数据驱动的阈值（如分位数），或直接用连续值让模型自己学。

同源反复强调（sleep_duration 同时出现在原始值、sleep_deficit、sleep_deprived、sleep_effectiveness 等中）是有意为之——树模型对不同表达方式可能在不同深度分裂。但实测表明这些扩展特征贡献微弱，可能过拟合。

**Q5: 数值交互 — 为什么选这些？为什么只有2个？**

和类别交互类似，是经验选择，选领域上可能相关的组合。3特征交互可以尝试（如 stress×sleep×exercise），但维度爆炸（7个数值取3个 = 35种组合），且容易过拟合。

**Q6: KMeans — 为什么 n_clusters=5？为什么只用数值？**

n_clusters=5 是经验选择，没有理论依据。KMeans 聚类不是在预测3个目标类——它是在发现数据的空间结构（哪些样本在特征空间中聚集在一起）。簇数和目标类数没有必然关系。

**为什么不用类别特征？** KMeans 用欧氏距离，类别特征没有自然的距离度量（"veg"和"non-veg"的距离是多少？）。可以做 one-hot 后参与，但维度膨胀。更专业的做法是用 KPrototypes（支持混合类型），但 sklearn 没有内置。

**Q7: KBins — 为什么是10个桶？**

经验选择，没有理论依据。10是常用值（对应十分位数）。太少（如3）信息损失大，太多（如100）接近原始值无意义。

**Q8: Target Encoding — 具体怎么转换的？**

TE 把每个类别取值转换为**该取值下每个目标类的条件概率**。以 stress_level 为例：

```
原始: stress_level = 'low'  (一个字符串)
TE后: stress_level_te_at-risk = 0.935  (low时at-risk的概率)
     stress_level_te_unhealthy = 0.050  (low时unhealthy的概率)
     stress_level_te_fit = 0.015       (low时fit的概率)
```

一个类别列 → 3 个数值列（因为有3个目标类）。这些数值直接告诉模型"当 stress=low 时，目标类的概率分布是什么"——比 LabelEncoder 的 0/1/2 编码信息量大得多。

## 1.5 模型体系

### 问题本质

这是一个**监督分类问题**（supervised classification），具体来说是**多类分类**（multiclass classification，3个类别），且**类别极度不平衡**（85.8% vs 8.36% vs 5.77%）。

不是聚类（无监督）、不是回归（连续值预测）、不是排序（learning to rank）。

### 模型选择分析

#### 考虑过但不适用的模型

| 模型 | 不适用原因 |
|------|-----------|
| KNN | O(n²) 复杂度，690K 行无法承受 |
| SVC (SVM) | O(n²~n³) 复杂度，690K 行无法承受 |
| Gaussian Process | O(n³) 复杂度，无法承受 |
| TabPFN v2 | 限制 <10K 行，690K 远超上限 |
| TabNet | 训练时间 >100 分钟，性价比低 |
| FT-Transformer | 训练时间 >100 分钟，性价比低 |
| AutoGluon | 训练时间 >1 小时，但**可能值得**（真正的跨家族多样性） |

#### 适用的模型及原理

**GBDT 家族（梯度提升决策树）** — 本项目的骨干

| 模型 | 核心原理 | 特点 |
|------|----------|------|
| XGBoost | 逐轮加法训练 CART 树，每轮拟合负梯度（残差），加 L1/L2 正则 | 通用性强，GPU 支持，early stopping |
| CatBoost | 有序提升（Ordered Boosting）减少预测偏移，原生处理类别特征 | 对类别特征最优，避免目标泄露 |
| LightGBM | 按叶生长（leaf-wise）而非层生长，直方图加速 | 训练最快，但容易过拟合小数据 |
| HistGB | sklearn 的直方图梯度提升，类似 LightGBM | 无需额外安装，与 sklearn 生态一致 |

**为什么 GBDT 适合？**
1. 天然处理混合特征（数值+类别）
2. 对缺失值鲁棒（自动学到最优分裂方向）
3. 对噪声特征鲁棒（通过分裂选择自动忽略无用特征）
4. 能捕获特征交互（多棵树的组合等价于高阶交互）
5. 训练速度快（直方图方法 + GPU）

**Neural 家族**

| 模型 | 核心原理 | 特点 |
|------|----------|------|
| RealMLP | PBLD 数值嵌入 + NTK 参数化线性层 + 余弦学习率 | NeurIPS 2024，预调优默认参数，CA delta 极大（+0.08） |
| sklearn MLP | 标准全连接网络 + 反向传播 | 太慢太弱（BA ~0.85） |

**为什么 RealMLP 有价值？** 它的归纳偏置与树模型完全不同：树模型学的是阶梯状决策边界，RealMLP 学的是光滑决策边界。当两者犯错的地方不同时，融合能互补。RealMLP 的 CA delta=+0.08 说明它的概率分布形状与树模型显著不同，CA 校准能从中提取更多信息。

**线性/生成家族**

| 模型 | 核心原理 | 特点 |
|------|----------|------|
| LogReg+Poly | 线性决策边界 + 多项式特征扩展 | 太弱（BA ~0.907），但真正不同的归纳偏置 |
| QDA | 假设每类服从不同高斯分布，二次决策边界 | 太弱（BA ~0.898），但生成模型视角 |

**特殊变体**

| 模型 | 核心原理 | 特点 |
|------|----------|------|
| XGB-OvR | One-vs-Rest：每类训练一个二分类 XGB，per-class scale_pos_weight | 不同损失函数 → 不同概率分布 |
| Focal-XGB | Focal Loss：降低易分类样本权重，聚焦难分类样本 | 对少数类更敏感，CA delta=+0.010 |

### 模型间相关性详解

**相关性衡量什么？** 两个模型预测的 argmax 结果的重合度（Cohen's kappa 或简单的一致率）。高相关 = 两个模型在同样的样本上犯同样的错误，融合无增益。

| 模型对 | 相关性 | 含义 |
|--------|--------|------|
| CatBoost vs XGB | 0.99+ | 几乎完全相同——同样的阶梯边界，同样的分裂点 |
| CatBoost vs HistGB | 0.99+ | 同上，都是 GBDT |
| CatBoost vs LGBM | 0.99+ | 同上 |
| XGB-OvR vs CatBoost | 0.97 | 略有不同（OvR 改变了损失函数） |
| Focal-XGB vs CatBoost | 0.94-0.96 | 有差异（Focal Loss 关注难样本） |
| RealMLP vs CatBoost | 0.93-0.96 | 差异最大（光滑 vs 阶梯边界） |
| Neo-LS-SVM vs CatBoost | 0.82 | 差异大但模型太弱 |

**核心瓶颈**：所有 GBDT 模型相关性 >0.99，融合几乎无增益。RealMLP 是唯一有实质性不同的模型，但它仍然在 97% 的分歧样本上站在树模型一边。

## 1.7 已验证的结论

### 有效的

1. **CA 校准是最大单项收益**（+0.001~0.002）
   - 原理见 1.2 节。本质是搜索 per-class 乘子优化 BA，纠正 argmax 对少数类的系统性低估。

2. **stress_x_activity 是最强特征**：近似 decision stump
   - **Decision stump** = 只有一个分裂节点的极简决策树。stress_x_activity 的 9 个桶中，6 个几乎纯 at-risk，1 个以 unhealthy 为主，3 个含 fit。仅凭这一个特征的桶均值就能达到 ~0.90+ 的 BA。它等价于一个 9 叶节点的浅树（深度 2），近似 decision stump。

3. **OOF Target Encoding 有效**：防止泄露的平滑编码
   - 原理见 1.4 节 Step 8。OOF 防止标签泄露，平滑防止小样本极端值。

4. **Early stopping 有效**：防止过拟合
   - 监控验证集指标，连续 N 轮不提升则停止。N=50-100 是常用范围。

5. **特征差异化微效**（+0.00010 on subsample）：不同模型用不同特征子集
   - CatBoost 用全特征，XGB 去掉 TE，HistGB 只用 top 特征。增加模型间差异性。

### 无效的

1. **Prior calibration hurt**（-0.0027）：V1 的先验匹配校准方法错误
   - V1 将预测概率乘以 (真实先验/预测先验) 来匹配训练分布。但 OOF 概率已经接近校准，强制匹配反而扭曲了。

2. **NNLS blend 失败**：权重分配异常
   - 非负最小二乘法将所有权重给 XGB（因为其概率绝对值最大），忽略了模型质量。

3. **Stacking hurt**（-0.0005~0.001）：LR meta-learner 在相关特征上=线性加权
   - 当基模型高度相关时，LR meta-learner 退化为简单的线性加权，不比直接平均好。

4. **降维 hurt**（-0.00020）：树模型本身对噪声免疫，降维破坏 CA 互补模式
   - 删除垃圾特征后，概率分布微变，CA 校准的互补模式被破坏。

5. **监督 stress 填补 hurt**（-0.00014）：模型已处理好 'missing' 类别
   - 用 CatBoost 预测缺失 stress 值，但 TE 已经给 'missing' 类别分配了最优概率，填补反而引入噪声。

6. **LGBM 无贡献**：与 XGB/CatBoost 高度相关，移除不影响结果

7. **更多树模型 ≠ 更好**：V4 加 2 个树模型仅 +0.00003

### 核心瓶颈

**所有模型误差高度相关**（0.93-0.998），加模型 ≈ 加噪声。突破 0.95 需要真正的跨家族多样性。

### 关于使用别人 CSV 的立场

**我同意这是作弊。** Kaggle Playground 系列的规则允许使用外部数据，但直接使用其他参赛者的预测结果（probability CSV）来提升自己的分数，本质上是"搭便车"——没有自己训练模型，只是做了后处理融合。这在规则上可能不违规，但在精神上违背了竞赛目的（学习和提升自己的建模能力）。我们应只使用自己训练的模型产出。
